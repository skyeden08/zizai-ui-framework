# 第二階段第 4 項：拖曳調整能力測試說明

## 目的

建立可獨立使用、獨立測試、可移除及替換的拖曳互動能力。能力只回報拖曳位移；被調整對象的寬度、位置及其他持續狀態由各使用位置自行保存與套用。

## 已確認的架構依據

依《UI模組架構規劃書》第五版：

- 通用框架能力包含共用外觀、開合、下拉選單、拖曳調整、事件處理；各自獨立，依需求選用。
- 單元職責明確，可獨立建置、使用、測試、替換及移除；組合不等於融合。
- UI 框架負責承載、組裝、配置與協調；單元保有自身職責、內部實作與測試。
- 容器不接管區域內部操作與內容邏輯；只處理跨區域空間協調與區域層級狀態。
- 桌面版左、中、右區可獨立調整寬度；中間區依剩餘空間調整。
- 跨單元協作透過明確介面；技術細節由執行 AI 依需求選擇。

## 能力邊界與介面

`src/capabilities/drag-adjustment.js` 提供：

`bindDragAdjustment({ handle, onDragStart, onDrag, onDragEnd })`

- `handle`：使用位置自行提供的拖曳操作把手。
- `onDragStart`：選用回呼，通知一次拖曳開始及起始指標座標。
- `onDrag`：必要回呼，接收相對於本次手勢起點的水平位移 `deltaX`、本次移動量 `movementX` 及目前指標座標。
- `onDragEnd`：選用回呼，通知拖曳結束或取消。
- 回傳解除連接函式，可獨立移除或替換。

能力只處理指標拖曳事件及回報位移，不讀取、不保存、不計算、不寫入被調整對象的寬度、位置或版面狀態；不修改對象樣式，不建立集中式拖曳管理單元或使用位置註冊表。使用位置在自己的回呼中自行更新寬度或位置。

## 靜態檢查

- 能力模組不含全域狀態、使用位置註冊表或集中式管理器。
- 能力模組不讀取或寫入目標寬度、位置、style 或 layout。
- 持續狀態只存在於測試使用位置的呼叫端。
- 事件連接有完整解除函式，支援移除及替換。
- 測試頁直接載入能力模組，不載入 `src/main.js`。
- 測試頁同時載入共用外觀、開合及下拉選單能力，以檢查組合使用。
- 測試程式涵蓋兩個以上使用位置的狀態獨立、拖曳互不影響、能力組合、取消、移除及替換。

## GitHub Pages 瀏覽器實測

公開測試頁：

`https://skyeden08.github.io/zizai-ui-framework/tests/drag-adjustment/`

瀏覽器實測項目：

1. 測試頁可正常開啟，能力模組、共用外觀及其他能力資源載入成功。
2. 測試結果由 `test-runner.js` 動態執行產生，不是預先寫死；記錄實際通過及未通過數。
3. 使用位置 A、B 各自提供不同初始寬度；拖曳 A 後，只有 A 自行保存及套用新寬度，B 不變。
4. 拖曳 B 後，只有 B 自行保存及套用新寬度，A 保留先前狀態。
5. 與共用外觀、開合、下拉選單組合操作，互不干擾。
6. 移除舊連接後拖曳不再觸發舊回呼；建立替換連接後，只有新回呼接收拖曳位移。
7. 指標取消或失去捕捉時，當次拖曳能結束，不留下作用中的手勢。
