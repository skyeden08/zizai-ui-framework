# 第二階段第 2 項：開合能力測試說明

## 目的

建立可獨立使用、測試及替換的開合能力，讓不同使用位置自行決定要呈現的內容，並自行持有及更新開合狀態。

## 已確認的架構依據

依《UI模組架構規劃書》第五版：

- 通用框架能力中的開合與其他能力各自獨立，依需求選用。
- 單元可獨立建置、使用、測試、替換及移除；組合不等於融合。
- 左、中、右區可獨立收合；上方區固定，不提供收合。
- 左側區內各項目可獨立開合。
- 各單元保有自身職責、內部實作與測試；容器不接管區域內部操作與內容邏輯。
- 採用 Web Components，不使用前端框架；跨單元協作透過明確介面。

## 能力邊界與介面

`src/capabilities/open-close.js` 提供兩個具名函式：

- `bindOpenClose({ trigger, getExpanded, onExpandedChange })`
  - 將原生按鈕的 click 操作轉成下一個開合狀態。
  - 狀態由使用位置透過 `getExpanded` 提供。
  - 使用位置透過 `onExpandedChange` 更新自己的狀態及內容呈現。
  - 回傳解除連接函式，可獨立移除或替換連接。
- `syncOpenCloseState(trigger, expanded)`
  - 同步按鈕的 `aria-expanded` 無障礙狀態。
  - 使用位置自行更新狀態後，可呼叫此函式同步狀態。

能力只處理操作觸發及按鈕無障礙狀態，不保存開合狀態，不建立或管理內容，不修改內容節點，也不管理其他使用位置。每個使用位置各自建立連接並持有自己的狀態。

## 靜態檢查

- 能力程式只匯出開合操作連接與無障礙狀態同步函式。
- 不存在全域狀態、使用位置註冊表、集中式控制器或跨位置狀態管理。
- 能力不建立、移除、隱藏或改寫使用位置的內容。
- 狀態由呼叫端提供及更新；連接解除函式可移除事件監聽，支援替換。
- 測試頁直接載入能力模組，不載入 `src/main.js`。
- 組合測試使用既有 CSS Variables，並與既有基本單元同頁檢查。
- 測試涵蓋獨立使用、各位置狀態隔離、內容責任保留、解除連接及替換。

## GitHub Pages 瀏覽器實測

公開測試頁：

`https://skyeden08.github.io/zizai-ui-framework/tests/open-close/`

瀏覽器實測項目：

1. 頁面可正常開啟，能力模組及 `variables.css` 請求成功（HTTP 200）。
2. 頁面自動執行測試，預期 11 項通過、0 項未通過。
3. 獨立使用：不載入 `src/main.js`，仍可開啟及關閉使用位置自行提供的內容。
4. 多個使用位置：操作其中一處，不改變另一處的狀態或內容。
5. 與共用外觀組合：開合操作正常，CSS Variables 樣式仍生效，兩項能力互不接管。
6. 與既有基本單元並存，不影響其載入及呈現。
7. 移除舊連接後，舊操作不再生效；建立新連接後可正常操作。
