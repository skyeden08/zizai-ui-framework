# 第三階段第 10 項｜各區獨立垂直捲動，中間區依剩餘空間調整

公開測試頁：
https://skyeden08.github.io/zizai-ui-framework/tests/region-independent-scroll/

## 本次定案與實作

- 中間區採 CSS Grid 彈性軌道 `minmax(0, 1fr)`，承接左、右區寬度軌道配置後的剩餘水平空間。
- 左、右區仍各自使用獨立寬度軌道；既有寬度請求仍由原介面送達容器。
- 剩餘空間由瀏覽器依 Grid 軌道自動分配，不新增 JavaScript 量測公式。
- 這是容器層可替換的空間配置選擇；日後改變分配方式，只需調整容器 Grid 配置，不需改動中間區內部或第 9 項介面。
- 容器只更新自身的 `grid-template-columns`。中間區內部呈現、內容與操作仍由中間區自身管理。
- 沿用第三階段第 9 項既有單向介面 `requestSpace`、`requestRegionState`，以及既有 `bindOpenClose`、`bindDragAdjustment`；未新增第二套協調機制，也未修改介面與能力的職責。
- 左、中、右區各自保有獨立的垂直內容捲動視窗與捲動位置。

## 測試涵蓋

測試頁會在瀏覽器中執行下列檢查：

1. 左、中、右區各自具有可垂直捲動的內容視窗。
2. 分別捲動任一區時，另外兩區的捲動位置不變。
3. 三區可同時保有不同的捲動位置。
4. 左、右區送出既有寬度請求後，中間區實際取得剩餘寬度；測試以容器及三區的瀏覽器實際版面尺寸核對。
5. 中間區內部操作由中間區自身處理，不觸發容器協調請求。
6. 容器調整 Grid 軌道前後，中間區內部節點保持不變。
7. 三區仍沿用第 9 項既有開合、拖曳能力及單向介面；容器只調整自身 Grid 軌道，沒有新增 JS 剩餘空間量測公式，也沒有操作中間區內部。

## 瀏覽器實測與驗收

請在 GitHub Pages 公開頁確認測試結果全部通過，並實際以滑鼠滾輪操作左、中、右區，確認捲動互不影響；再操作中間區內部控制，確認其操作自主。測試頁的自動檢查不取代使用者的實際操作驗收。

## 仍待使用者確認

- 捲動樣式細節。
- UI 正式層級對應。

上述兩項不影響本次已定案的 CSS Grid 剩餘空間配置方式。
