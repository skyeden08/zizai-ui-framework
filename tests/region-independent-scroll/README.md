# 第三階段第 10 項｜各區獨立垂直捲動，中間區依剩餘空間調整

公開測試頁：
https://skyeden08.github.io/zizai-ui-framework/tests/region-independent-scroll/

## 本次可實作範圍

- 左、中、右區各自具有自己的內容捲動視窗與 scrollTop。
- 三區的捲動位置互不影響。
- 中間區內部操作仍由中間區自身處理，不由容器接管。
- 沿用第三階段第 9 項既有的單向區域至容器介面，以及既有開合、拖曳能力；不新增第二套空間協調機制。

## 本次未定案範圍

中間區依剩餘水平空間調整的具體計算方式，規劃書未明定，待使用者確認。本次未實作該計算，也不宣稱此部分通過。

捲動樣式細節（例如捲軸外觀及其他呈現細節）規劃書未明定，待使用者確認。本次只建立獨立捲動所需的基本內容捲動視窗，不自訂捲軸外觀。

## 靜態檢查

- 容器提供可限制內容高度的版面區域。
- 左、中、右區各自具有獨立內容捲動視窗。
- 三區未共用同一個捲動狀態或捲動容器。
- 三區仍組裝既有 `bindOpenClose`、`bindDragAdjustment`。
- 三區仍透過既有 `requestSpace`、`requestRegionState` 單向介面與容器協作。
- 未修改既有介面及開合、拖曳能力的職責。
- 未新增區域間連接或第二套空間協調介面。
- 中間區剩餘空間計算未實作，明確保留待定。

## 瀏覽器實測

請在 GitHub Pages 公開頁實際操作：

1. 分別以滑鼠滾輪捲動左、中、右區；確認每次只有操作區的內容移動。
2. 先後捲動三區，確認三區可保有不同捲動位置；回到任一區操作時，另外兩區位置不變。
3. 在中間區執行其內部操作，確認操作仍由中間區處理，沒有改變其他區域或容器的內部狀態。
4. 核對頁面結果中的第 9 項既有機制檢查，確認沿用原有單向介面及能力，沒有另寫一套。
5. 中間區取得剩餘空間的實際版面測試：待具體計算方式確認後補做；不得把本次其他測試結果視為此項通過。

測試頁會以動態結果列出已執行、未通過及待定項目。頁面自動檢查不取代使用者在瀏覽器的實際操作驗收。
